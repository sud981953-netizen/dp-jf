# 技能更新流程

> 本文件是工作流细则。触发方式：老师提供新版技能包路径，或直接说"更新dp-jf技能""升级dp-jf""/dp-jf-update"。所有相对路径基于技能根目录。

## 什么时候需要更新

当你收到新版dp-jf技能包时，需要更新本地的技能文件。

## 更新流程

### Step 1：识别版本

```
IF 老师提供了新版技能包的路径:
  -> 读取新版包的 version.md
  -> 读取本地已安装的 version.md
  -> IF 新版本号 > 已安装版本:
       -> 进入Step 2（更新）
  -> IF 新版本号 == 已安装版本:
       -> "当前已是最新版本，无需更新"
  -> IF 已安装版本号 > 新版本:
       -> "新版本低于当前版本，确定要降级吗？"
       -> 等老师确认后再进入 Step 2
ELIF 老师直接说"更新/升级":
  -> 问老师要新版包路径
  -> "请提供新版dp-jf技能包的存放路径"
  -> 阻塞等待
```

### Step 2：备份旧版

```
1. 读取当前已安装版本号（从 version.md）
2. 在技能文件夹的同级目录创建备份文件夹：
   dp-jf_backup_{旧版本号}/
   （原则：备份必须在技能扫描路径之外，防止被识别成第二个同名技能）
3. 备份以下文件：
   - SKILL.md
   - workflow/（全部）
   - 要素定义库/（全部）
   - templates/（全部）
   - scripts/（全部）
   - 源文档（00_短视频内容创作72变.md）
   - version.md、changelog.md
4. 备份完成后，把备份文件夹里的 SKILL.md 改名为 SKILL.md.bak
   （备份只做存档，不参与技能识别——防止扫描路径里出现两个
   同名 dp-jf 技能，导致 /dp-jf 调用指向不明）
5. 备注：学员数据（存件地址下的学员文件夹）不需要备份（不受影响）；
   config/设置.md 是本机私有设置，不备份也不覆盖
```

### Step 3：应用新版文件

```
1. 从新版包路径复制以下文件到当前技能文件夹：
   - 覆盖：SKILL.md、workflow/*、要素定义库/*、templates/*、scripts/*、源文档/*
   - 新增：新版包中的新增文件
   - 删除：新版包中已废弃的文件（如有）
2. 保留以下文件不动：
   - config/设置.md（本机存件地址等设置，跨版本延续）
   - 存件地址下的所有学员文件夹（学员数据原地不动）
3. 复制完毕后读取新版 version.md
```

### Step 4：验证并输出更新报告

```
1. 检查关键文件是否存在：
    - SKILL.md、version.md
    - workflow/ 全部工作流文件（phase00/phase0/phase1/phase2/phase3/特别警告/技能更新流程）
    - 要素定义库/ 全部28个要素文件（00-27号）
2. 检查关键Phase是否正确：Phase 00、Phase 0/1/2/3
3. 检查旧版本痕迹（唯一指向检查）：
    - 备份文件夹内的 SKILL.md 已改名为 SKILL.md.bak
    - 技能扫描路径内，name: dp-jf 的 SKILL.md 只剩一份（当前新版）
    - 新版文件中没有残留指向旧版本的调用命令/触发字段
    -> 确认 /dp-jf 现在唯一指向 v{新版本}
4. 路由回归测试（改动涉及要素文件增删或路由表调整时必做）：
    - 按 tests/路由测试题库.md 的方法，新开对话抽跑错题高发的题（升级只改了局部时，至少跑对应分组的题）
    - 全量路由改动（新增要素文件/改路由表）必须全量跑，90分以上才算更新成功
5. 输出更新报告：

## dp-jf 更新完成

### 更新内容
（从 changelog.md 读取当前版本的新增内容）

### 版本记录
v{旧版本} → v{新版本}

### 调用确认
- /dp-jf 现在指向 v{新版本}（最新版）
- 旧版本已失效为纯备份存档，不参与调用

### 注意事项
- 学员数据不受影响
- config/设置.md 保留，存件地址无需重新提供
- 本次更新内容详见 changelog.md
- 备份文件位于 dp-jf_backup_{旧版本}/（技能文件夹同级），如需回退可告知AI
```

### Step 5：尺寸体检 + 自检清单（防膨胀）

```
【尺寸体检】
- SKILL.md ≤ 500 行（硬上限）。主文件是路由器，内容塞进主文件等于让每次对话都背着全库跑
- SKILL.md 净涨幅 ≤ 100 行（超了说明塞了不该塞的内容，应进 workflow/ 或要素库）
- 单个要素定义文件 ≤ 500 行（超了说明内容太杂，考虑拆分）
- 单个 workflow 文件 ≤ 300 行（超了说明流程耦合太重，考虑拆分）
- 检查有没有历史叙事段（X版本起Y上线这类）——有就删掉，归 changelog.md

【自检清单】
- [ ] SKILL.md 中提到的每个要素定义库文件都真实存在
- [ ] SKILL.md 中提到的每个 templates/ 文件都真实存在
- [ ] SKILL.md 中提到的每个 workflow/ 文件都真实存在
- [ ] 每个 Phase（00/0/1/2/3）的触发条件在 SKILL.md 中有明确定义，细则在 workflow/ 对应文件中
- [ ] 文件结构列表中的文件名和实际文件名完全一致
- [ ] version.md 的版本号 >= 更新前的版本号
- [ ] changelog.md 包含本次更新的变更记录
- [ ] 本次改动涉及的要素文件，其内容变化已同步到 21_方法论总览.md（分组表描述+场景路由行）和 tests/路由测试题库.md（预期答案）——双索引单方面改动算未完成
- [ ] 有模板的产出物（作业卡/视频评价/账号策划等）只认 templates/ 一份格式源，SKILL.md/workflow 内嵌的格式块均为速览并指向模板（无完整格式双源残留）
- [ ] 学员数据未被动过；config/设置.md 未被覆盖
- [ ] 备份文件夹 dp-jf_backup_{旧版本}/ 已在技能文件夹同级创建
- [ ] 备份文件夹内的 SKILL.md 已改名为 SKILL.md.bak（不会产生第二个同名技能）
- [ ] 技能目录中 name: dp-jf 的 SKILL.md 仅存在一份（新版），/dp-jf 唯一指向最新版
- [ ] 新版文件中无指向旧版本的调用命令/触发字段残留

哪条打不了勾，回去修。
```

## 更新后建议

- 更新完成后，建议老师明天早上试用一次每日巡检
- 如果更新后遇到问题，告诉AI"回退到上一版本"
- 回退操作：从备份文件夹恢复文件到当前技能文件夹（先把备份里的 SKILL.md.bak 改回 SKILL.md 再覆盖）

## 关于 skill 安装的逻辑说明（给开发者参考）

第一次安装：
1. 老师把整个 dp-jf 文件夹发送给 AI
2. AI 安装到自己的技能目录（确保 SKILL.md 位于技能文件夹根目录，name: dp-jf 只出现一份）
3. 安装完成后先跑一次「启动自检」（见 SKILL.md），确认要素定义库/templates/workflow/scripts 四个目录都能读到
4. 告知老师使用方法

后续更新：
1. 老师收到新版 dp-jf 包（来自开发者）
2. 老师通过上述更新流程升级
3. 不需要重新安装，更新保留学员数据和本机设置
