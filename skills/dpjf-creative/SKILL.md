# dpjf-creative：72变与创意拍法

拍法的任务是把内容主线变成观众能看见的画面。形式服务内容，编号不证明质量，复杂不等于更好。

## 一、先锁定内容与制作条件

提取：

- 选题、目标观众和主要观看回报；
- 本条最核心的“筹码”：哪句话、哪件事、哪个动作或哪件产品最吸引人；
- 可用物件、场景、人物、素材和设备；
- 时间、预算、剪辑能力、出镜意愿和授权；
- 未拍、可补拍、不可补拍及已有原话。

缺少会改变拍法的信息先问老师。不知道学员有什么素材时，不能默认有门店、员工、客户或专业设备。

## 二、核对72变源文

用户指定变法或需要使用72变时：

1. 读取 `共享资源/要素定义库/06_72变要素.md` 的标签和索引；
2. 到 `共享资源/00_短视频内容创作72变.md` 核对真实条目、名称、结构和原例；
3. 记录编号、核心结构、适用条件和需要改造的素材；
4. 找不到就明说，不能根据编号猜名字。

索引是候选，不是效果保证。第59变并入第6变的历史口径按源文处理，不另造第59变。

## 三、匹配而不是硬套

逐项检查：

| 检查 | 问题 |
|---|---|
| 内容匹配 | 这个结构能否突出核心筹码和主要回报 |
| 观众匹配 | 目标观众能否迅速看懂，形式会不会喧宾夺主 |
| 素材匹配 | 学员现有事实和物件能否兑现 |
| 条件匹配 | 时间、场地、人员、设备和剪辑能否承担 |
| 意愿与合规 | 是否符合出镜意愿、隐私、授权和行业要求 |

一般推荐一个最适配方案。多个候选必须说明真实取舍，不凑数。没有合适变法时使用普通过程展示，并明确未使用72变。

## 四、设计横向与纵向信息

横向信息是口播、文字和论证；纵向信息是同一秒出现的场景、人物、动作、道具、字幕和声音。

先保留核心内容，再考虑怎样用真实画面降低理解成本：

- 抽象理论能否用实物或关系比喻；
- 观点能否落到一个人的动作和情绪；
- 方法能否变成可观察步骤；
- 产品差异能否用细节、操作或使用过程展示；
- 画面是否能补充证据，而不是只作装饰。

不要为增加信息密度堆放无关元素，也不使用虚构客户、危险动作或未经授权的人物画面。

## 五、写到能拍出来

输出镜头顺序，每个镜头写：

```text
画面｜口播／字幕｜所需素材｜作用
```

同时给：

- 准备什么；
- 先拍什么、后拍什么；
- 预计准备和拍摄时间；
- 哪些镜头可以删减；
- 完成标准是什么。

每日完整定制作业包要逐镜头对应口播／字幕、真实素材、作用和预计用时，并保留文案使用的语料结构，不能把语料原句当成学员自己的话。

不露脸时优先使用手部、实物、过程、屏幕、旁白和字幕。已拍不可补时只能使用已有原话和画面，保持操作顺序；不能通过创意名义新增镜头。

## 六、难度降级

方案超出条件时依次减少：

1. 地点和人物；
2. 道具和转场；
3. 镜头数量；
4. 口播和字幕负担；
5. 后期效果。

仍无法完成时换成能保留核心信息的最简单形式，不把“再努力一点”当解决方案。

## 七、输出契约

```markdown
**推荐拍法**：{名称；是否72变及真实编号}
**为什么适合**：{内容筹码和学员条件}

**准备**：{真实素材和授权}

**镜头**
1. 画面：……
   口播／字幕：……
   作用：……

**预计负担**：{准备和拍摄时间}
**完成标准**：{可检查的提交结果}
**待确认**：{仅有影响项}
```

用户只问某变法是什么时，只解释真实条目、适用和限制，不附整套作业。

## 八、质量自检

- 是否突出核心筹码而非形式炫技？
- 72变是否实际核对源文？
- 每个镜头是否有真实素材和明确作用？
- 是否尊重不出镜、时间、隐私和制作状态？
- 是否能在当前条件下完成，且有降级路径？
