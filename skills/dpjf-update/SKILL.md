# dpjf-update：技能包版本与更新

## 一、三种入口

- 本地查询：只读包根 `version.json`；
- 检查更新：读取经用户或维护者确认的来源，比较版本和内容，不写入；
- 执行更新：用户明确要求时，按授权和备份流程执行。

“更新学员档案”不属于本 Skill。

## 二、可信来源与当前状态

当前 `remote_source` 为空时，不猜远端仓库或最新版本。历史 Git 远程不能自动证明本地候选已发布。只查本地版本时不联网。

执行更新前读取 `维护/更新说明.md`，核对真实安装路径、当前改动、候选来源和回退点。目标有未提交修改时不能用当前提交冒充完整备份。

## 三、可回退更新

1. 确认来源、目标和用户授权；
2. 快照相关文件并记录校验；
3. 在独立位置准备候选；
4. 逐项核验主路由、子技能、共享资料和脚本；
5. 保留学员资料、用户配置、原始素材和未知文件；
6. 应用获准变更；
7. 运行结构和行为验证；
8. 输出更新回执，失败时按备份恢复。

禁止硬重置、清理未知文件或按旧清单自动删除。

## 六、更新成功后只保留最新版

只有最新版安装、结构、脚本和实际入口验证全部成功后，才预览并清理 `dp-jf`、`dpjf-*`、`dojf*` 及对应旧备份目录。先运行 `python scripts/cleanup_old_versions.py --current-root "<最新版目录>"` 核对清单，再仅对确认范围加 `--apply`。

清理不得触及其他技能、学员资料父目录、未知文件或当前最新版。链接只删除链接本身，不删除真源。更新失败或验证不完整时保留旧版和备份，不执行清理。

技能包不内置 `学员/`；首次使用由用户提供学员资料父目录，不由更新流程代建或清理。

## 四、有效迭代证据

修改 Skill 方法时保留：

- 修改前后规则全文；
- 同一输入和实际输出；
- 人的具体负反馈；
- 新增测试和旧回归结果。

不能因单个案例不断打补丁，也不能只凭文件变长宣称质量提升。

## 五、回执

报告版本、来源、实际变更、校验等级、保留项、失败项和回退位置。未执行行为验证时只能写“结构校验通过”。
