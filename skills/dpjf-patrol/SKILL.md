# dpjf-patrol：多学员每日巡检

巡检回答：今天先处理谁、依据是什么、下一步是什么。它不是把旧档案复述一遍，也不是给全班自动生成大量作业。

## 一、固定数据范围

确认：

- 要查看哪些学员和记录；
- 截止时间及查询范围；
- 读取权限；
- 老师是要总览、重新扫描还是展开某人。

路径只是材料，不自动等于巡检命令。目录、身份或索引未设置时先通过 `dpjf-student`，不能盲猜。

## 二、按人归集证据

从老师自然语言同步、档案、作业、评价和钉钉记录中提取：

- 作业及完成状态；
- 待评价作品；
- 老师承诺和约定期限；
- 学员问题、情绪和明确诉求；
- 最近记录时间及未覆盖范围。

重名、昵称、同音字无法唯一对应时停止归集该人，先确认。没提到不等于没事，旧记录不证明实时状态。

## 三、优先级判断

依次处理：

1. 明确退款、投诉、心理危机或其他紧急风险；
2. 时间敏感的承诺和已到期事项；
3. 已有作品的评价与约定交付；
4. 普通作业推进；
5. 观察和待确认项。

每个排序都写实际原因和下一步，不用固定“连续几天没交＝故意拖延”“播放低＝内容失败”等规则替代证据。

## 四、清单与展开

老师版每行包含：

```text
学员｜已知事实及时间｜今日动作｜待确认
```

风险学员可附一段可复制回复。全班总览控制密度，不默认展开所有完整作业卡。

老师指定某人后，只继承该学员事实和限制，再交给作业、评价或沟通能力，不串入其他学员的信息。重新扫描必须实际重新读取，不能凭上次结果假装刷新。

## 五、写入与读取分开

巡检默认只读。需要更新档案时，用户必须明确要求，并通过 `dpjf-student` 完成：

- 唯一身份；
- 目标文件和范围；
- 来源和授权；
- 路径校验；
- 写后回读。

原始聊天、合同和证据不覆盖；旧记录不当作当前事实直接替换。

## 六、输出契约

```markdown
## 今天先处理
1. {学员}：{事实和时间}
   动作：{一步}
   待确认：{仅有影响项}

## 正常推进
{按真实记录列出}

## 覆盖范围
{读取了哪些记录，哪些未核验}
```

## 七、停止条件

- 学员或资料范围不能唯一确定；
- 记录权限不足；
- 需要写入但未明确授权；
- 身份冲突或证据冲突会改变动作；
- 老师要求完整实时状态，但实际只能看到历史资料。
