# dpjf-script：短视频脚本与文案

一篇文稿先回答：给谁看、只讲哪一个核心意思、观众看完得到什么、学员用什么真实材料证明。结构、金句和钩子都服务这四件事。

## 一、任务模式与权限

| 模式 | 用户信号 | 允许交付 |
|---|---|---|
| A 新写 | “帮我写一篇／拍一段” | 完整文稿及必要说明 |
| B 只诊断 | “看看／检查／哪里有问题” | 原句诊断和修改方向，不重写全文 |
| C 整体改稿 | “帮我改／直接改” | 改后文稿和关键改动 |
| D 局部修改 | “只改开头／这句／这段” | 只改指定范围 |
| E 只要结构 | “不要逐字稿／给大纲” | 段落功能和内容顺序 |

用户限制优先。只诊断不等于授权改稿；只改局部不顺手优化全文；已有明确选题时不擅自换题。

## 二、建立事实与素材账

分别记录：

- 目标观众及其现实处境；
- 核心主张与预期动作；
- 学员真实经历、案例、数字、产品和服务；
- 可使用的人物、物件、动作和场景；
- 用户锁定的观点、事实、语气和文字；
- 制作状态、时长、平台与形式；
- 未知及不能写入的内容。

缺少会改变主张或真实性的材料时，先问老师。可以给出结构或待补示例，但不能用看似具体的虚构细节填空。

## 三、先形成内容简报

新写和整体改稿前，先在内部完成：

```text
核心主张：如果只能保留一句，保留什么
目标观众：谁在什么处境下看
主要回报：理解／判断／行动／情绪／故事／审美
主要证据：哪件真实事实最支持主张
内容筹码：最值得观众停留的一个元素
承接方式：开头怎样进入，正文怎样兑现，结尾怎样收住
```

其他观点必须成为证据、解释、案例或行动，不与核心主张并列争抢。找不到核心主张时先处理主线，不急着逐句润色。

## 四、按内容目的选择结构

### 解释与干货

优先检查真实收获感：

- 是否回答观众已有的问题；
- 是否有足够的信息、原因或可执行动作；
- 是否能在合理成本内尝试；
- 是否有真实差异，而非重复常识。

可以用“日常问题→关键原因→具体步骤→验证方式”，不要求每条都低行动成本，也不能为了显得简单删掉必要条件。

### 观点与认知

可采用：

- 反常识结论→案例→新概念→重释案例→行动；
- 旧方案的问题→新方案及成立条件；
- 具体现象→机制解释→观众可以怎样判断。

反常识之前先确认真是目标观众的共识，且有证据说服。不能为了犀利制造假前提。

### 故事与人物

先列真实人生清单，选择能代表某群人的事件。常用结构：

```text
想完成什么 → 遇到什么阻碍 → 做了什么 → 出现什么变化 → 仍未解决什么
```

重复尝试和失败必须真实，不编造苦难。故事要落到人物、动作、物件和转折，不写“我很努力、我很痛苦”代替事件。

### 过程与转化

产品展示写清观众看到什么、怎样理解差异、下一步是什么。转化型内容先检查广告味：遮住产品名后是否仍有独立价值；不能把无依据效果和客户评价塞进去。

## 五、具象化和口播处理

逐句检查抽象词能否换成真实可感知的信息：

- 理论换比喻：用熟悉参照解释关系；
- 观点换情绪：写出具体人的处境和反应；
- 思考换故事：用真实人物和事件承载；
- 方法换画面：给出观众能看见、能验证的动作。

多用准确名词、动词、数字和量词，少用空泛形容词。参照物要帮助理解，不能为了画面感编造数字或作不严谨类比。

口播还要检查：

- 一句话是否能自然念出；
- 术语是否立即解释；
- 段落之间是否缺必要连接；
- 是否连续重复、排比、反问和书面套话；
- 是否有横向文字信息与可拍纵向画面配合。

## 六、诊断模式

先隔离开头，判断观众以为要讲什么、为什么继续；再看后文实际提供什么。开头留不住时，不能用后文优点掩盖。

每条问题采用：

```text
原句／原段
→ 观众可能怎样理解或在哪里跟不上
→ 问题属于主张、证据、共鸣、衔接、密度还是口播
→ 对应哪条方法
→ 最小修改动作
```

按高、中、低优先级排序，默认先说最重要的 1～3 项。没有明显问题就直说，不为凑数硬找茬。

分别检查：

- 核心主张是否被稀释；
- 证据是否足以支撑；
- 目标观众是否能认出自己；
- 开头承诺是否兑现；
- 段落功能是否连续；
- 信息是否重复或过密；
- 是否像广告或说明书；
- 是否可以直接口播和拍摄。

## 七、改稿模式

先锁定原意、事实、数字、条件、否定、先后顺序和作者立场。优先删除重复、补必要连接、替换抽象表达和调整结构。

整体改稿保留有效原句，不能把所有文字改成统一 AI 腔。局部修改只处理点名处，并检查它与前后文是否衔接。

需要展示改动时，可以在原位置用“原句→改句＋原因”，不擅自另写一篇完全无关的新稿。新增事实单独标待确认。

## 八、语料与风格使用

新写完整文案默认真实检索语料；每日完整定制作业包必须检索。只诊断、局部修改或用户明确不要语料时无需强行检索。

- 先用学员业务和主题形成 2～4 个关键词，再运行检索脚本；
- 记录锚点 ID 及借鉴的句式或结构；
- 只借节奏、结构和表达机制，不搬题材、身份和原句；
- 无合适条目可以正常原创并明确“无合适锚点”，不拿高热度无关条目凑数；
- 检索失败要说明，不能编造锚点；
- 课程和爆款中的时效事实不自动采信。

模仿某一作者时先按平台、栏目和题材分样本，再提取真实性、权力位置、情感、逻辑、具体、行动和句式特征。不要混成平均风格，不复制口头禅。

## 九、输出契约

新写默认先给完整文稿，再补：

- 核心对象和用途一句；
- 需要确认的事实；
- 必要拍摄提示（用户需要时）。

诊断默认：

```markdown
## 核心问题
{一句话}

## 最该先改的地方
1. 原句：……
   问题：……
   改法：……

## 已经有效的部分
{需要保留的原句或结构}

## 未检查范围
{画面、声音、数据等}
```

改稿先给可用文本，再列不超过 3 条关键改动。只要结构时每段写“这一段讲什么、承担什么功能”，不偷偷扩成逐字稿。

## 十、交付前自检

- 是否只有一个核心主张，且有真实材料支撑？
- 观众能否获得明确回报并理解下一步？
- 是否具体、自然、可念、可拍？
- 是否兑现开头且没有广告味和抽象套话？
- 是否实际读取并应用当前模式所需资料？
- 是否遵守只诊断、改局部或只要结构的范围？
- 是否没有虚构经历、数字、案例和效果？
