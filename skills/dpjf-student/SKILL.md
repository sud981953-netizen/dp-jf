# dpjf-student：学员资料、身份与证据基础设施

本 Skill 管学员资料怎样被找到、核对、补充和安全写入。任何涉及具体学员的文件或钉钉任务，都不能凭上下文猜测目录和身份。

## 一、核心原则

1. **先身份，后资料**：学员不唯一时，不读、不写、不归集。
2. **先证据，后判断**：老师陈述、钉钉原消息、本地档案和模型推断分别保存。
3. **先授权，后动作**：读取、写入、下载和发送是不同权限，读取不自动授权写入。
4. **不知道就问**：缺父目录、群、昵称或关键事实时，向教务老师或用户确认，不盲猜。
5. **文件只进学员目录**：任何文件都不能写入宿主默认目录或另一个学员目录。

## 二、模式选择

| 模式 | 触发 | 交出 |
|---|---|---|
| A 初始化资料库 | 第一次处理学员资料 | 父目录、索引、分类结构 |
| B 新学员建档 | 新学员进入 | 学员文件夹及钉钉身份映射 |
| C 证据补充 | 学员具体提问、评价、规划或复盘 | 带来源和未知项的证据包 |
| D 文件写入 | 生成或更新学员文件 | 校验后的路径和回读回执 |
| E 身份消歧 | 重名、改昵称、换群、目录不明 | 最少确认问题，暂停相关读写 |

普通方法问答不强制初始化。只要涉及具体学员文件或钉钉消息，必须先完成 A/B。

## 三、初始化资料库

请用户提供一个专门管理学员资料的总父目录。它必须满足：

- 是用户明确选择的本地目录；
- 可以包含多个以学员名称命名的子文件夹；
- 不是技能包安装目录、系统目录或宿主默认输出目录；
- 用户授权读取；需要创建或写入时另有明确授权。

将父目录保存在本机私有配置，不写入公开分发包。之后复用配置，不重复询问。

标准结构：

```text
{父目录}/
├── _dpjf/
│   ├── 学员索引.json
│   └── 设置.json
├── {学员甲}/
│   ├── 学员档案.md
│   ├── 00_对话存档/
│   ├── 01_账号策划/
│   ├── 02_选题与文案/
│   ├── 03_作业与排期/
│   ├── 04_视频评价/
│   ├── 05_复盘记录/
│   ├── 06_素材与作品/
│   └── 07_钉钉证据/
└── {学员乙}/
```

`_dpjf` 只存索引和配置，不冒充学员。已有其他目录和原始文件保持不动，不为了套结构强行迁移。

## 四、新学员建档

必须先取得：

1. 学员姓名；
2. 所在钉钉群，优先真实群 ID，同时记录群全名；
3. 学员在该群中的昵称。

可选记录历史昵称、姓名变体和备注。业务访谈可以随后进行，不用 20 项问卷阻塞建档。

### 核验顺序

1. 父目录已设置；
2. 学员文件夹没有无法解释的同名冲突；
3. 钉钉群通过真实返回唯一确定；
4. 群昵称能与该学员对应；不能仅凭相似昵称自动认定；
5. 保存群 ID、群名、昵称、别名、核验状态和日期；
6. 获得创建授权后建立学员目录和索引；
7. 回读索引，报告路径与核验状态。

群 ID 未拿到时可先用群全名查询，多候选就停止。昵称变更时追加别名和生效日期，不改写历史消息中的原昵称。换群时保留旧群关系，不用新群覆盖历史证据来源。

## 五、证据补充流程

### 1．整理老师当次信息

提取当前问题、学员原话或老师转述、材料、时间、目标、限制和保存要求。老师本次信息作为当前输入，不能被旧档案覆盖。

### 2．确定补充范围

根据问题决定钉钉查询范围：

- 当前状态：优先近期消息；
- 作业或作品：定位对应日期、主题、文件名或学员原话；
- 方案质疑：查此前承诺、方案说明和学员反馈；
- 退款投诉：优先学员明确诉求及前后文，不等待完整建档再回应；
- 阶段复盘：按指定时间范围汇总，不能用近期片段代替整个阶段。

需要指定群近期消息时，用钉钉群消息读取；需要按关键词、发送者或时间筛选时，用消息搜索；跨消息、文档等来源时，用钉钉 AI 搜问。所有命令以真实工具返回为准，保留群、发送者、时间、数量、完整性和错误。

### 3．读取实际消息

- 核对群 ID 和发送者昵称；
- 保留学员原话及消息时间；
- 片段不足以判断时读取前后文；
- 搜索无结果只说明当前条件未命中；
- 无权限或工具失败时说明未核验范围；
- 不把其他群成员的话当成学员本人立场。

### 4．形成证据包

```markdown
## 当前任务
{老师要什么}

## 老师本次提供
- {事实或转述，含来源}

## 钉钉补充
- {学员原话、时间、群、覆盖范围}

## 本地档案
- {仍有效的背景及最近更新时间}

## 新增或冲突
- {钉钉补充了什么；哪些事实不一致}

## 推断与未知
- {哪些是判断；哪些仍需确认}
```

冲突会影响行动时，先向老师确认；无法确认时给条件性判断，不静默选择一方。

## 六、文件路径闸门

每次创建、修改、移动或下载文件前执行：

1. 确认用户要求产生文件，对话回答不等于授权写文件；
2. 确认父目录和唯一学员；
3. 确认产物分类；
4. 用 `scripts/student_files.py resolve` 取得路径；
5. 用 `check` 验证目标仍位于该学员目录；
6. 按用户授权选择新建或更新，不覆盖未知文件；
7. 写后回读并报告学员、相对路径、动作和校验结果。

示例：

```bash
python scripts/student_files.py resolve \
  --root "<学员资料父目录>" \
  --student "张三" \
  --category "02_选题与文案" \
  --filename "20261103_口播稿.md"
```

禁止：

- 父目录缺失时写默认目录；
- 学员重名时选择最像的一项；
- 文件名包含 `../` 或绝对路径；
- 把“先不要保存”理解成先写临时文件；
- 把下载的钉钉资源写到技能包或另一个学员目录。

宿主支持写入前 Hook 时，应对 Write/Edit 等动作再做路径拦截；不支持时，文件写入必须经闸门，不得绕过。

## 七、档案维护边界

- 原始聊天、合同、投诉证据、签字件和历史导出不普通去重、改名或删除；
- 当前档案可以更新当前状态，但历史事实和来源要保留；
- 方案使用版本和日期，避免拿错旧版；
- 视频评价保留成长记录；
- 用户未明确要求存档时，不因完成回答自动写入；
- 学员数据、索引和私有配置不进入公开分发包。

## 八、停止条件

- 学员、群、昵称或目录不能唯一确定；
- 需要的关键事实会改变结论，且尚未确认；
- 读取或写入权限不足；
- 目标路径不在对应学员目录；
- 证据冲突会改变行动；
- 用户明确限制读取、保存或发送。

停止时说明已经知道什么、缺什么、向谁确认以及为什么，不能盲猜继续。
