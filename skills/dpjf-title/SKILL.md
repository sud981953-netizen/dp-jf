# dpjf-title：标题、封面与开头

标题、封面和开头共同决定观众是否进入内容以及能否看懂主线。先确定这件事讲给谁、凭什么值得看，再写文字。不能指望包装救一篇没有素材的稿子。

## 一、先确定任务范围与制作状态

### 用户要什么

- 发布界面的文字标题；
- 封面上的文字及换行；
- 视频第一句或前几秒口播；
- 多项组合；
- 只改现有某一项。

只改一项时只交该项，不自动附送其他模块。

### 当前处于什么状态

| 状态 | 允许动作 |
|---|---|
| 只有素材或大纲 | 先确定主线和素材，标暂定 |
| 有稿未拍 | 可调整正文并新写开头 |
| 已拍可补 | 优先利用现有素材，再列最小补拍 |
| 已拍不可补 | 只用真实原话和可见画面，不能新造口播 |
| 长录制中截短视频 | 先确定同一段主线，不拼接无关段落 |

状态未知且会改变交付时，只问这一项。已有答案不重复问。

## 二、建立素材账

从正文、履历、案例和业务资料中提取五类素材：

1. **数据**：真实数字、规模、时间、结果；
2. **权威**：真实资质、机构、经历和可核实背书；
3. **金句**：能独立成立、便于复述的判断；
4. **认知冲突**：与目标观众已有理解不同的解释；
5. **痛点**：目标人群正在经历的具体处境和代价。

履历和正文是两个不同输入。正文没有可信度素材时，可以向老师要真实履历；没有取得前不能编。所有数字、身份和结果必须能追溯到材料。

同时保留原标题和原强句作为比较基准。新文字没有明确优势时保留原句。

## 三、先定主线和观众

用一句话写清：

```text
这条内容给哪类人看，呈现什么事，观众看完得到什么
```

检查：

- 主题词能否筛选正确的人；
- 最强素材是否支持这个主线；
- 开头承诺能否由正文兑现；
- 吸引来的人是否与业务或账号目标相容；
- 是否会因追求更大人群而把评论区带偏。

方向未定且材料足够时，最多给 4 个有实质差异的方向，各写“面向谁、用哪处素材、正文能否兑现”。用户选定后再出成品。用户指定方向或说“直接出”时跳过菜单。

## 四、A／B 类处理

- **A 类**：真实事件、反差或战绩本身足够强，直接说，不堆公式；
- **B 类**：日常内容，需要把最强素材前置并选择合适角度。

写不出合格标题时，不机械多写 20 个。先判断缺的是素材、正文主线还是标题表达，并明确告诉用户。

## 五、按平台形态分配任务

不要把“吸引人”当成所有位置的同一任务。根据用户实际看到内容的顺序判断：

| 位置 | 主要任务 | 文字要求 |
|---|---|---|
| 小红书标题与封面 | 在多选一中帮助目标观众决定点击 | 一眼看懂，可留悬念但不误导，两个位置尽量互补 |
| 抖音／视频号发布文案 | 配合画面，让目标观众愿意继续 | 与开头同主线，不重复堆砌 |
| 抖音主页封面 | 让观众在主页快速识别内容 | 像目录，能区分不同视频 |
| 视频号封面与短标题 | 在缺少另一个元素时也能独立成立 | 各自说清主题，避免依赖同屏信息 |
| B 站标题与封面 | 帮助观众判断内容价值与差异 | 信息完整，不故意省略关键对象 |

字数是展示约束，不是质量公式。需要时按平台当前实际限制核对字符，不把课程中的固定字数当永久规则。

## 六、标题制作

标题可以留悬念，但不能误导：

- 用目标观众熟悉的词；
- 把最强且能被正文证明的信息放在合适位置；
- 可以突出结果、问题、反差、对象或具体细节；
- 不用未证实的“第一、唯一、100%”；
- 不把正文没有的经历、身份和效果加进去；
- 不用“大家都、无数人、90% 的人”等没有依据的泛化。

候选要有信息重点差异，不做同义替换凑数。

## 七、开头制作

开头是内容的试用装，独立回答：

1. 这条视频讲什么；
2. 为什么值得继续；
3. 为什么可以听这个人讲。

可以包含话题＋Hook＋可信度，但不必机械三段。未拍时可新写，附下一句和接回正文的位置。根据本人语速和口播习惯控制长度，不把“5 秒固定多少字”套给所有人。

已拍可补时先给现有素材方案，再列最小补拍；已拍不可补时：

- 只引用用户提供的原话；
- 标明原话位置或顺序，不编时间码；
- 说明接回哪一句；
- 保持准备、操作、因果和故事顺序；
- 声画是否匹配标待核看。

教程不能把准备步骤移到操作之后。无法保证连贯时保留原顺序。

## 八、输出契约

默认一屏交完成品：

```markdown
**方向**：{给谁看、讲什么}

**正文建议**（未拍且确有必要，最多 3 条）
- ……

**标题**
1. {成品} — {一句理由}

**封面文字**
```text
{保留换行}
```

**开头**
{口播或原话}
接回：{正文哪一句／哪一段}
```

只要单项时删除其他章节。用户要求多平台时按实际平台分别给，不把同一条文字无差别复制。

## 九、交付前验收

- 字符数和换行是否满足指定限制；
- 开头是否独立成立且正文能兑现；
- 数字、身份、案例是否有材料依据；
- 标题和封面是否服务同一主线而非互相矛盾；
- 已拍内容是否只使用真实原话且顺序连贯；
- 是否避免未经证实的流量、效果和绝对化承诺；
- 是否只交用户点名的范围。
